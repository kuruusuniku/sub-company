# ブラウザ統合ガイド

## 概要
品質管理部のQAレビューにおいて、ブラウザベースの視覚的テストを実施するためのガイド。

## Phase 1: gstackとの併用（短期）

### 前提条件
- gstackがグローバルインストールされていること
- `~/.claude/skills/gstack` が存在すること

### 利用可能なgstackコマンド

| コマンド | 用途 | 品質管理部での活用場面 |
|---------|------|---------------------|
| `/browse` | Chromiumベースのブラウザ操作 | 対象ページへのアクセス・操作 |
| `/qa` | git diffから影響ページ特定→テスト→修正 | 成果物の視覚的検証 |
| `/qa-only` | テスト報告のみ（コード変更なし） | 品質レポート作成 |
| `/benchmark` | Core Web Vitals・パフォーマンス | パフォーマンス品質ゲート |
| `/canary` | デプロイ後監視 | リリース後のヘルスチェック |

### 品質管理部のQAスキルでの呼び出し方

品質管理部のサブエージェントが対外向けWeb成果物をレビューする際、
以下の条件でブラウザテストを提案する:

1. 成果物がWebアプリケーション・Webページの場合
2. UIの視覚的変更を含む場合
3. ユーザーが明示的にブラウザテストを要求した場合

呼び出し手順:
1. 対象URLまたはローカルサーバーの起動を確認
2. gstackの `/qa-only` でスクリーンショット付きテストレポートを取得
3. レビュー結果にスクリーンショットとヘルススコアを含める

### gstack未インストール時のフォールバック
gstackがインストールされていない場合:
- ブラウザテストをスキップし、通常のコードベースレビューのみ実施
- ユーザーに「gstackをインストールするとブラウザベースのQAが利用可能」と案内
